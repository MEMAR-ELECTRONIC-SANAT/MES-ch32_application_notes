چکیده — CH32H417 نخستین MCU عمومی دو‌هسته‌ای شرکت WCH است؛ با معماری دو‌هسته‌ای RISC-V خانوادۀ QingKe (V5F + V3F) و سه قابلیت سخت‌افزاری در سطح هسته: سمافور سخت‌افزاری (HSEM)، ارتباط بین پردازنده‌ها (IPC) و حفاظت از حافظه فیزیکی (PMP). این قابلیت‌ها پشتیبانی سخت‌افزاری لازم را برای همکاری هماهنگ دو هسته، دسترسی ایمن به منابع مشترک و افزایش پایداری سیستم فراهم می‌کنند و اساس بهره‌برداری مؤثر از مزایای معماری دو‌هسته‌ای‌اند. این سند کاربردهای اصلی، سازوکار عملکرد و روش‌های اولیۀ استفاده از هر قابلیت را برای توسعۀ ثانویه (Secondary Development) جمع‌بندی می‌کند.
مقدمه
توضیحات و دامنۀ کاربرد

میکروکنترلر CH32H417 نخستین MCU عمومی دو‌هسته‌ای شرکت WCH (Nanjing Qinheng Microelectronics) است که از معماری دو‌هسته‌ای RISC-V خانوادۀ QingKe بهره می‌برد و از دو هسته V5F + V3F تشکیل شده است.

این تراشه به سه قابلیت سخت‌افزاری در سطح هسته مجهز شده است:

۱. HSEM (Hardware Semaphore): سازوکار سمافور سخت‌افزاری برای هماهنگ‌سازی و مدیریت دسترسی هم‌زمان دو هسته به منابع مشترک.
۲. IPC (Inter-Processor Communication): ارتباط بین پردازنده‌ها برای تبادل داده و هماهنگی عملیات میان دو هسته.
۳. PMP (Physical Memory Protection): حفاظت از حافظه فیزیکی برای کنترل و محدودسازی دسترسی هسته‌ها به نواحی مختلف حافظه.

این قابلیت‌ها پشتیبانی سخت‌افزاری لازم را برای همکاری هماهنگ دو هسته، دسترسی ایمن به منابع مشترک و افزایش پایداری سیستم فراهم می‌کنند و اساس بهره‌برداری مؤثر از مزایای معماری دو‌هسته‌ای هستند. این سند با هدف معرفی کاربردهای اصلی، سازوکار عملکرد و روش‌های اولیه استفاده از هر یک از این قابلیت‌ها تدوین شده است و می‌تواند به‌عنوان مرجعی برای توسعۀ نرم‌افزارهای مبتنی بر CH32H417 (Secondary Development) مورد استفاده قرار گیرد.

بخش ۱
سمافور سخت‌افزاری HSEM

◆۱.۱ کاربرد اصلی و نقش

HSEM (Hardware Semaphore) سازوکار سمافور سخت‌افزاری است و عمدتاً مسائل رقابت و هم‌گام‌سازی منابع در سیستم دو‌هسته‌ای را حل می‌کند.

کاربرد اصلی:

تک‌دیگرپرهی منابع: حفاظت از منابع بحرانی مانند جانبی‌های مشترک و حافظۀ مشترک؛ جلوگیری از به‌هم‌ریختگی داده در نوشتن هم‌زمان دو هسته.
هم‌گام‌سازی راه‌افت: اطمینان از راه‌افت V3F و V5F طبق زمان‌بندی پیش‌بینی‌شده و پرهیز از دسترسی به منابعِ مقداردهی‌نشده.
بیداری کم‌مصرف: آزادکردن سمافور می‌تواند وقفه بسازد و هستۀ دیگر را از حالت STOP/STANDBY بیدار کند.

ویژگی‌ها:

منطق کاملاً سخت‌افزاری؛ بدون سربار چرخش نرم‌افزاری (spin).
پشتیبانی از گرفتنِ تک‌دستوری سریع (FastTake).
پشتیبانی از حالت وقفه؛ آزادسازی سمافور به‌طور خودکار وقفۀ هستۀ مقابل را می‌سازد.
کانال‌های سمافور مستقلِ متعدد که به منابع مختلف تخصیص‌شدنی‌اند.

◆۱.۲ سازوکار عملکرد و روش اولیۀ استفاده

◆۱.۲.۱ سازوکار عملکرد

هر سمافور دو وضعیت دارد: آزاد (FREE) و اشغال‌شده (TAKEN).

گرفتن (Take): اگر سمافور آزاد باشد بلافاصله اشغال و موفقیت بازمی‌گردد؛ اگر اشغال باشد، بسته به حالت، شکست (FastTake غیرمسدودکننده) یا انتظار (حالت مسدودکننده) بازمی‌گردد.
آزادسازی (Release): سمافور به وضعیت آزاد برمی‌گردد؛ می‌توان پیکربندی کرد تا وقفه‌ای برای اطلاع‌رسانی به هستۀ دیگر ساخته شود.

◆۱.۲.۲ روش اولیۀ استفاده

۱) هم‌گام‌سازی دو‌هسته‌ای: V3F نخست اجرا می‌شود، پس از مقداردهی سیستم، V5F را بیدار می‌کند و با WFE وارد انتظار می‌شود؛ پس از راه‌افت، V5F سمافور را می‌گیرد و آزاد می‌کند، وقفه ساخته می‌شود و V3F بیدار می‌شود.

/******************** کد هستۀ V3F ********************/ int main(void) { SystemInit(); // فعال‌سازی وقفۀ سمافور 0 HSEM_ITConfig(HSEM_ID0, ENABLE); // پیکربندی بیداری رویداد (بدون تابع سرویس وقفه هم بیدار می‌شود) NVIC->SCTLR |= 1 << 4; // بیدارکردن هستۀ V5F NVIC_WakeUp_V5F(Core_V5F_StartAddr); // ورود به انتظار کم‌مصرف برای آمادۀ شدن V5F RCC_HB1PeriphClockCmd(RCC_HB1Periph_PWR, ENABLE); PWR_EnterSTOPMode(PWR_Regulator_ON, PWR_STOPEntry_WFE); // پس از آزادسازی سمافور توسط V5F به اینجا بیدار می‌شود HSEM_ClearFlag(HSEM_ID0); while(1) { // حلقه اصلی } } /******************** کد هستۀ V5F ********************/ int main(void) { SystemInit(); // گرفتن سریع سمافور 0 HSEM_FastTake(HSEM_ID0); // آزادسازی سمافور 0؛ وقفۀ V3F را می‌سازد و آن را بیدار می‌کند HSEM_ReleaseOneSem(HSEM_ID0, 0); while(1) { // حلقه اصلی } }
کد ۱هم‌گام‌سازی راه‌افت دو هسته با HSEM

۲) دسترسی متقابل به منابع: پیش از دسترسی به جانبی مشترک (مثل SPI، UART) یا حافظۀ مشترک سمافور گرفته می‌شود و پس از پایان کار آزاد می‌شود.

// پیش از دسترسی به منبع مشترک while(HSEM_ReadStatus(HSEM_ID1) != FREE); // انتظار با پرس‌وجو HSEM_Take(HSEM_ID1); // گرفتن سمافور // === بخش بحرانی: کار با منبع مشترک === // برای مثال: خواندن/نوشتن بافر مشترک، پیکربندی جانبی مشترک HSEM_Release(HSEM_ID1); // آزادسازی سمافور
کد ۲دسترسی متقابل به منابع با HSEM

◆۱.۲.۳ نکات

HSEM_FastTake غیرمسدودکننده است؛ در صورت شکست در گرفتن، بلافاصله بازمی‌گردد و باید مقدار بازگشتی بررسی شود.
وقفۀ سمافور می‌تواند فقط برای بیداری به‌کار رود و تابع سرویس وقفه نوشته نشود (همراه با بیت بیداری رویداد در SCTLR).
توصیه می‌شود به منابع مختلف، شناسۀ سمافور متفاوت داده شود و از استفادهٔ تودرتویی که به بن‌بست (deadlock) می‌انجامد پرهیز شود.
بخش ۲
ارتباط بین پردازنده‌ها IPC

◆۲.۱ کاربرد اصلی و نقش

IPC (Inter-Processor Communication) ارتباط بین پردازنده‌ها از مسیر صندوق پیام است؛ با ۴ کانال ارتباطی مستقل، اطلاع‌رسانی دستور و انتقال دادهٔ کوچک میان دو هسته را فراهم می‌کند.

کاربرد اصلی:

اطلاع‌رسانی پیام: یک هسته به هستۀ دیگر سیگنال رویداد می‌فرستد و وقفه می‌سازد.
انتقال دادهٔ کوچک: 4×32bit داده؛ مناسب برای فرستادن دستور، وضعیت و اشاره‌گر آدرس.
ارتباط دوطرفه: هر کانال از دریافت و ارسال دوطرفه پشتیبانی می‌کند و وقفه‌ها مستقل‌اند.

تفاوت با حافظۀ مشترک:

IPC یک کانال پیامِ سبک با اطلاع‌رسانی وقفه است و برای فرستادن دستورهای کنترلی مناسب است.
حافظۀ مشترک (512KB SRAM مشترک) برای تبادل داده‌های حجمی مناسب است.
در پروژه‌های واقعی معمولاً ترکیبی استفاده می‌شود: IPC برای اطلاع‌رسانی + حافظۀ مشترک برای انتقال داده.

◆۲.۲ سازوکار عملکرد و روش اولیۀ استفاده

◆۲.۲.۱ سازوکار عملکرد

IPC از سازوکار صندوق پیام (Mailbox) بهره می‌گیرد:

شامل ۴ رجیستر دادهٔ ۳۲ بیتی (MSG0~MSG3) است.
فرستنده پس از نوشتن داده، رجیستر ارسال را فعال می‌کند و وقفۀ گیرنده ساخته می‌شود.
گیرنده در وقفه داده را می‌خواند، پس از پردازش پرچم وقفه را پاک می‌کند.
از دو حالت وقفه پشتیبانی می‌کند: وقفۀ دریافت و وقفۀ ارسال.

◆۲.۲.۲ روش اولیۀ استفاده

روند نمونۀ ارتباط:

توصیه‌های استفاده:

تقسیم کار کانال‌ها: برای سناریوهای کاربردی مختلف کانال مستقل تخصیص دهید (مثلاً کانال ۰ = دستورهای کنترلی، کانال ۱ = اطلاع‌رسانی جریان داده).
انتقال دادهٔ بزرگ: IPC فقط «اطلاع آماده‌بودن داده» و آدرس را می‌فرستد؛ دادهٔ واقعی در SRAM مشترک گذاشته می‌شود.
اولویت وقفه: اولویت وقفۀ IPC نباید خیلی بالا باشد تا جانبی‌های زمان‌محور مختل نشوند.
سازوکار راستی‌آزمایی: برای دستورهای حیاتی می‌توان کلمۀ بررسی (check) اضافه کرد تا تداخل به فعال‌سازی اشتباه نینجامد.
بخش ۳
حفاظت از حافظه فیزیکی PMP

◆۳.۱ کاربرد اصلی و نقش

PMP (Physical Memory Protection) سازوکار استاندارد حفاظت از حافظه فیزیکی در RISC-V است و می‌تواند برای نواحی حافظه مجوز خواندن، نوشتن و اجرا تعیین کند و از دسترسی غیرمجاز جلوگیری کند. هسته‌های V5F و V3F در CH32H417 هر یک ۴ کانال PMP داخلی دارند.

کاربرد اصلی:

جداسازی حافظه: تقسیم ناحیۀ کد، ناحیۀ داده و ناحیۀ جانبی‌ها با مجوزهای متفاوت.
پیشگیری از عملیات اشتباه: جلوگیری از نوشتۀ تصادفی برنامه در فلش یا نواحی دادهٔ فقط‌خواندنی.
افزایش پایداری: دسترسی غیرمجاز مانند عبور اشاره‌گر از مرز و سرریز پشته، استثنا می‌سازد نه «پروازِ بی‌صدا».
حفاظت امنیتی: محافظت از رجیسترهای پیکربندی حیاتی در برابر تغییر توسط کدِ غیرمجاز.
توجه: روی بستر CH32H417 فقط هستۀ V5F از PMP پشتیبانی می‌کند.

◆۳.۲ سازوکار عملکرد و روش اولیۀ استفاده

◆۳.۲.۱ سازوکار عملکرد

هر کانال PMP از رجیستر آدرس (pmpaddr) و رجیستر پیکربندی (pmpcfg) تشکیل شده است:

رجیستر آدرس: آدرس آغاز و دامنۀ ناحیۀ حفاظت را تعریف می‌کند.
رجیستر پیکربندی: مجوزها (R/W/X)، حالت تطبیق آدرس و بیت قفل را تنظیم می‌کند.

تعریف بیت‌های مجوز:

R (Read): اجازۀ خواندن؛ W (Write): اجازۀ نوشتن؛ X (Execute): اجازۀ واکشی و اجرا؛ L (Lock): قفل‌کردن پیکربندی تا ریست.

حالت‌های تطبیق آدرس:

حالت هم‌ترازی طبیعی با دقت ۴ بایت.
سه حالت پشتیبانی‌شده: TOR (بازۀ بالایی)، NA4 (ناحیۀ ۴ بایتی) و NAPOT (ناحیۀ توان‌دوم هم‌تراز).
