چکیده — سیستم فایل FatFs به‌عنوان لایۀ میانی، API استاندارد فایل را به لایۀ کاربرد ارائه می‌کند و تفاوت رسانه‌ها را در لایۀ diskio.c منزوی می‌سازد. این سند انتقال آن را روی دو رسانه شرح می‌دهد: SPI FLASH (سکتور منطقی 4096 بایت، جابه‌جایی 1536 سکتوری و ظرفیت 10MB روی W25Q128) و کارت SD با SDIO (درایو DEV_MMC و قالب FM_FAT32) — همراه با کد کامل، پیکربندی ffconf.h، جدول تفاوت‌های دو کانال و گام‌های عیب‌یابی و راستی‌آزمایی.
مقدمه
توضیحات و دامنۀ کاربرد

این یادداشت کاربردی (Application Note) شرح می‌دهد که چگونه در پروژه‌های سری CH32V (معماری RISC-V با کتابخانۀ استاندارد پیرامونی SPL) در محیط MounRiver Studio، سیستم فایل FatFs منتقل (Port) شود. بر اساس رسانۀ ذخیره‌سازی، موضوع به دو دسته تقسیم می‌شود: SPI FLASH و کارت SD کنترل‌شده با رابط SDIO؛ هر دو از یک لایۀ میانی مشترک FatFs بهره می‌گیرند و تفاوت‌ها صرفاً در درایو رسانه و سازگارسازی diskio.c متمرکز است.

نام تمام رابط‌ها، ماکروها، تعریف پایه‌ها و کدهای فرمان در این سند از روال‌های واقعی کتابخانۀ الگو (درایو SPI Flash، روال SDIO و روال FatFs) برگرفته شده و می‌توان مستقیماً آن‌ها را در پروژه به کار برد؛ هیچ توصیف حدسی در متن وجود ندارد. برای خواندن این سند، آشنایی با زبان C و نحوۀ استفاده از کتابخانۀ استاندارد CH32V لازم است. در جریان انتقال، فایل اصلی FatFs یعنی ff.c را دست‌نخورده بگذارید و کل کار سازگارسازی را در diskio.c و ffconf.h متمرکز کنید.

◆توضیح مختصر فنی

این بخش افزودۀ مترجم برای درک بهتر مفاهیم سند است و در متن اصلی وجود ندارد.

۱. سیستم فایل چیست؟

سیستم فایل (File System) سازوکاری برای سازمان‌دهی داده‌ها روی رسانۀ ذخیره‌سازی به‌صورت فایل و پوشه است؛ به لایۀ کاربرد امکان می‌دهد بدون آگاهی از چیدمان فیزیکی بایت‌ها روی رسانه، فایل را با نام بسازد، بخواند، بنویسد یا حذف کند. FAT و FAT32 از رایج‌ترین سیستم‌های فایل در میکروکنترلرها و کارت‌های SD هستند.

۲. FatFs چیست؟

FatFs ماژول میان‌افزار متن‌باز پیاده‌سازی سیستم فایل FAT برای سیستم‌های نهفته است. این ماژول از سخت‌افزار کاملاً مستقل است: در بالا مجموعه رابط‌های استاندارد f_mount، f_open، f_read، f_write و … را ارائه می‌کند و در پایین، عملیات خواندن/نوشتن را از طریق توابع ثابت disk_* به لایۀ درایو رسانه می‌سپارد؛ به همین دلیل فقط با نوشتن یک لایۀ نازک، روی هر رسانه‌ای نصب می‌شود.

۳. نقش diskio.c و ffconf.h

diskio.c پل میان FatFs و درایو رسانه است و توابع disk_status، disk_read، disk_write و disk_ioctl را برای رسانۀ مشخص پیاده‌سازی می‌کند؛ ffconf.h نیز پیکربندی امکانات ماژول (اندازۀ سکتور، تعداد درایوها، صفحۀ کد، نام فایل طولانی و …) را در اختیار می‌گیرد. تمام تفاوت‌های دو پروژۀ این سند در همین دو فایل خلاصه می‌شود.

◆۱.۱ هدف انتقال و رویکرد کلی

هدف انتقال آن است که لایۀ کاربرد بتواند از طریق رابط‌های استاندارد FatFs (f_mount، f_open، f_read، f_write و …) به رسانۀ ذخیره‌سازی دسترسی داشته باشد و تفاوت رسانه‌ها در لایۀ diskio.c منزوی شود. FatFs یک لایۀ میانی است که در بالا API فایل ارائه می‌کند و در پایین از طریق رابط ثابت ورودی/خروجی دیسک، درایو رسانه را فرا می‌خواند.

۱.۱.۱ ساختار لایه‌ای

ساختار لایه‌ای FatFs در شکل ۱ نشان داده شده است. تفاوت دو پروژه فقط در لایۀ درایو رسانه و شمارۀ درایو فیزیکی و پارامترهای سکتور در diskio.c است؛ بدنۀ FatFs کاملاً یکسان باقی می‌ماند.

◆۲.۲ اندازۀ سکتور و جابه‌جایی نشانی

۲.۲.۱ سکتور 4KB و خواندن-تغییر-نوشتن

برخلاف کارت SD، این پروژه اندازۀ سکتور منطقی FatFs را 4096 بایت تنظیم می‌کند تا با گرانول پاک‌سازی SPI FLASH یکسان باشد؛ یعنی FF_MIN_SS برابر 512 و FF_MAX_SS برابر 4096. بدین ترتیب طول نوشتنِ متناظر با هر disk_write مضرب 4KB است و از خواندن-تغییر-نوشتن در مرز بلوک‌های پاک‌سازی اجتناب می‌شود.

پاک‌سازی درون یک بلوک اجتناب‌ناپذیر است: در SPI FLASH هنگام نوشتن فقط می‌توان 1 را به 0 تبدیل کرد و پیش از نوشتن باید پاک‌سازی انجام شود. تابع SPI_Flash_Write() این مورد را از پیش مدیریت می‌کند؛ روند آن در شکل ۲ آمده است.

شکل ۲روند پردازش نوشتن تک‌بلوکی در SPI_Flash_Write (برچسب‌ها مطابق سند اصلی)

بنابراین در disk_write مستقیماً SPI_Flash_Write فراخوانی می‌شود و نیازی به پیاده‌سازی منطق بافر و پاک‌سازی در diskio.c نیست. بافر مربوطه در این پروژه آرایۀ سراسری SPI_FLASH_BUF[4096] است و 4KB از RAM را اشغال می‌کند.

۲.۲.۲ جابه‌جایی 1536 سکتوری و ظرفیت قابل استفاده

فایل diskio.c این پروژه پیش از هر خواندن/نوشتن، به‌طور یکنواخت sector += 1536 اجرا می‌کند؛ یعنی شمارۀ سکتور منطقی به‌کلی 1536 سکتور 4KB (معادل 6MB) به جلو رانده می‌شود. بدین ترتیب سیستم فایل از منطقۀ بعد از 6MB استفاده می‌کند و 6MB نخست برای کاربردهای دیگر (مانند برنامه، ناحیه پارامتر یا داده‌ای دیگر) باقی می‌ماند تا با داده‌های موجود تداخل نکند.

با در نظر گرفتن مقادیر بازگشتی disk_ioctl، پارامترهای واقعی سیستم فایل عبارت‌اند از: GET_SECTOR_COUNT برابر 2560، GET_SECTOR_SIZE برابر 4096 و GET_BLOCK_SIZE برابر 1. بنابراین ظرفیت سیستم فایل 2560 × 4KB = 10MB است و بازۀ 6MB تا 16MB را اشغال می‌کند؛ دقیقاً متناظر با W25Q128 ظرفیت 16MB. برای استفاده روی قطعه‌هایی با ظرفیت دیگر، باید دو پارامتر «جابه‌جایی» و «شمارۀ کل سکتورها» هم‌زمان تنظیم شوند.

◆۲.۳ سازگارسازی diskio

شمارۀ درایو فیزیکی این پروژه SPI_FLASH = 0 تعریف شده است؛ بنابراین مسیر نصب "0:" است. نکات پیاده‌سازی پنج رابط به شرح زیر است:

#define SPI_FLASH 0 /* SPI FLASH mapped to physical drive 0 */ DSTATUS disk_status (BYTE pdrv) { switch (pdrv) { case SPI_FLASH : id = SPI_Flash_ReadID(); /* 0xEF13 ~ 0xEF17 hit: clear STA_NOINIT */ ... } }

در disk_read، پیش از خواندن جابه‌جایی اعمال و نشانی بایت محاسبه می‌شود:

DRESULT disk_read (BYTE pdrv, BYTE *buff, LBA_t sector, UINT count) { case SPI_FLASH : sector += 1536; SPI_Flash_Read(buff, sector << 12, count << 12); res = RES_OK; }
DRESULT disk_write (BYTE pdrv, const BYTE *buff, LBA_t sector, UINT count) { case SPI_FLASH : sector += 1536; write_addr = sector << 12; SPI_Flash_Write((u8 *)buff, write_addr, count << 12); res = RES_OK; } DRESULT disk_ioctl (BYTE pdrv, BYTE cmd, void *buff) { case SPI_FLASH : case CTRL_SYNC: break; case GET_SECTOR_COUNT: *(DWORD*)buff = 2560; break; case GET_SECTOR_SIZE: *(WORD*)buff = 4096; break; case GET_BLOCK_SIZE: *(WORD*)buff = 1; break; case CTRL_TRIM: break; }
نکته: نوع پارامتر طولِ SPI_Flash_Read و SPI_Flash_Write برابر u16 است، درحالی‌که disk_read/disk_write مقدار count << 12 می‌دهند؛ سقف شمارۀ سکتور در هر فراخوانی حدود 15 سکتور است (15 × 4096 = 61440 و 16 × 4096 از ظرفیت ۱۶ بیتی بیرون می‌زند). اگر کاربرد شما خواندن/نوشتن پیوستۀ بزرگ دارد، بهتر است نوع پارامتر طول درایو به u32 تغییر کند یا در diskio.c به تکه‌های ۱۵ سکتوری تقسیم و حلقه‌وار فراخوانی شود.

◆۲.۴ نمونۀ نصب و خواندن/نوشتن

روند اصلی برنامه چنین است: مقداردهی اولیۀ SPI و فلش، تشخیص مدل، نصب، قالب‌بندی در صورت نبود سیستم فایل، ساختن فایل، نوشتن و خواندن باز. کد کلیدی به این صورت است:

SPI_Flash_Init(); Flash_Model = SPI_Flash_ReadID(); /* print model; print Fail! on error */ SPI_Flash_Erase_Sector(0); opt.fmt = FM_FAT; opt.n_fat = 1; opt.align = 0; opt.au_size = 0; res_sd = f_mount(&fs, "0:", 1); if (res_sd == FR_NO_FILESYSTEM) { res_sd = f_mkfs("0:", &opt, work, sizeof(work)); if (res_sd == FR_OK) { res_sd = f_mount(&fs, "0:", 1); } } res_sd = f_open(&fnew, "0:/testWCH.txt", FA_CREATE_ALWAYS | FA_WRITE); res_sd = f_write(&fnew, WriteBuf, 11, &fnum); f_close(&fnew); res_sd = f_open(&fnew, "0:/testWCH.txt", FA_OPEN_EXISTING | FA_READ); res_sd = f_read(&fnew, ReadSDBuf, 11, (UINT *)&fnum);

در این پروژه WriteBuf برابر رشتۀ "Hello WCH!" (11 بایت) است و پس از خواندن، داده بایت‌به‌بایت چاپ و مقایسه می‌شود. پارامتر قالب‌بندی FM_FAT است و اندازۀ بافر work برابر FF_MAX_SS (در این پروژه 4096) است.

۳.۱.۲ ساعت و رابط درایو

تقسیم فرکانس ساعت و حالت کار در sdio.h تعریف شده‌اند: SDIO_INIT_CLK_DIV برابر 0xB2 برای ساعتِ آهستۀ مرحلۀ مقداردهی اولیه و SDIO_TRANSFER_CLK_DIV برابر 0x00 برای مرحلۀ انتقال؛ حالت کار نیز SD_POLLING_MODE یا SD_DMA_MODE انتخاب می‌شود. رابط بیرونی درایو شامل SD_Init، SD_GetState، SD_GetCardInfo، SD_ReadDisk، SD_WriteDisk و متغیر سراسری SDCardInfo است (با اعضای CardType، CardCapacity، CardBlockSize، RCA و SD_cid).

◆۳.۲ سازگارسازی diskio

این پروژه قرارداد شمارۀ درایو نمونۀ FatFs را حفظ کرده است: DEV_RAM برابر 0، DEV_MMC برابر 1 و DEV_USB برابر 2؛ کارت SD از DEV_MMC استفاده می‌کند و مسیر نصب "1:" نوشته می‌شود. نکات پیاده‌سازی رابط‌ها به شرح زیر است:

#define DEV_MMC 1 /* SD card mapped to physical drive 1 */ DSTATUS disk_status (BYTE pdrv) { case DEV_MMC : result = SD_GetState(); if (result < SD_CARD_DISCONNECTED) { stat &= ~STA_NOINIT; } else { stat = STA_NOINIT; } }
DRESULT disk_read (...) { case DEV_MMC : result = SD_ReadDisk(buff, sector, count); /* SD_OK mapped to RES_OK */ } DRESULT disk_write (...) { case DEV_MMC : result = SD_WriteDisk((u8 *)buff, sector, count); }

پارامترهای disk_ioctl از ساختار اطلاعات کارت گرفته می‌شود:

case GET_SECTOR_COUNT: *(DWORD*)buff = SDCardInfo.CardCapacity / 512; break; case GET_SECTOR_SIZE: *(WORD*)buff = SDCardInfo.CardBlockSize; break; case GET_BLOCK_SIZE: *(WORD*)buff = SDCardInfo.CardBlockSize; break;

تابع get_fattime() در این پروژه مقدار ثابت 0 را برمی‌گرداند.

نکته: پارامتر شمارۀ سکتورِ SD_ReadDisk و SD_WriteDisk از نوع u8 است، درحالی‌که disk_read/disk_write مقدار UINT count می‌دهند؛ درخواستِ بیش از 255 سکتور در یک فراخوانی کوتاه (Truncate) می‌شود. برای خواندن/نوشتن پیوستۀ بزرگ، بهتر است پارامتر درایو به u32 تغییر کند و در diskio.c به تکه‌های کوچک‌تر تقسیم شود.

◆۳.۳ نمونۀ نصب و خواندن/نوشتن

روند اصلی با کانال SPI FLASH یکسان است؛ تفاوت در شمارۀ درایو و قالب قالب‌بندی است:

while (SD_Init()) { printf("SD Card Error!\r\n"); delay_ms(1000); } show_sdcard_info(); /* print card type, ManufacturerID, RCA, capacity, block size */ opt.fmt = FM_FAT32; opt.n_fat = 1; opt.align = 0; opt.au_size = 0; res_sd = f_mount(&fs, "1:", 1); if (res_sd == FR_NO_FILESYSTEM) { res_sd = f_mkfs("1:", &opt, work, sizeof(work)); if (res_sd == FR_OK) { res_sd = f_mount(&fs, "1:", 1); } } res_sd = f_open(&fnew, "1:/testWCH.txt", FA_CREATE_ALWAYS | FA_WRITE); res_sd = f_write(&fnew, WriteBuf, 11, &fnum); f_close(&fnew); res_sd = f_open(&fnew, "1:/testWCH.txt", FA_OPEN_EXISTING | FA_READ); res_sd = f_read(&fnew, ReadSDBuf, 11, (UINT *)&fnum);

قالب قالب‌بندی این پروژه FM_FAT32 است و با FM_FAT پروژۀ SPI FLASH تفاوت دارد؛ اندازۀ بافر work نیز برابر FF_MAX_SS (در این پروژه 512) است. در صورت شکست SD_Init، پیام "SD Card Error!" به‌طور حلقه‌ای چاپ می‌شود و پس از ۱ ثانیه تأخیر، دوباره تلاش می‌شود.
