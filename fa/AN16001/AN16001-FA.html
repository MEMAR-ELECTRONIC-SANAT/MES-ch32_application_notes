توضیحات و دامنۀ کاربرد

گذرگاه میان‌مدارهای یکپارچه (I2C) و نسل بهبودیافتهٔ آن (I3C) هر دو پروتکل‌های ارتباط سریال همگام‌اند و به‌طور گسترده برای اتصال سنسورها، شتاب‌سنج‌ها، تراشه‌های لمسی و جانبی‌های کم‌مصرف به کار می‌روند. هر دو در لایۀ فیزیکی از دو خط سیگنال استفاده می‌کنند: خط ساعت SCL و خط دادهٔ SDA؛ اما I3C ضمن حفظ سازگاری پسینی، کارایی گذرگاه، مصرف توان و قابلیت‌های مدیریت را به‌طور چشمگیری تقویت کرده است. این سند ساختار، ویژگی‌ها و تفاوت‌های دو گذرگاه را شرح می‌دهد و نحوۀ درایو دستگاه‌های I2C روی سخت‌افزار I3C میکروکنترلرهای CH32 را همراه با کد نمونه مرور می‌کند.

◆۱.۱ I3C چیست؟

I3C (Improved Inter-Integrated Circuit) را اتحادیۀ MIPI در سال 2017 منتشر کرده است؛ استاندارد تکاملی I2C که ساختار دومیلۀ SCL/SDA را حفظ می‌کند و تغییرات آن بر سه محور متمرکز است:

سرعت: زمان‌بندی و قالب فریم لایۀ فیزیکی بازتعریف شده است؛ در حالت SDR نرخ انتقال تا 12.5Mbit/s می‌رسد؛

مدیریت: پشتیبانی از نشانی پویا، وقفۀ درون‌گذرگاهی و چند‌کنترل‌گری؛

سازگاری: هم‌زیستی با دستگاه‌های متعارف I2C روی یک گذرگاه.

◆۱.۲ محدودیت‌های I2C

برای آنکه جایگاه I3C روشن شود، نخست باید دید I2C در کاربرد واقعی با چه محدودیت‌هایی روبه‌روست. جدول زیر مشکلات رایج این گذرگاه را همراه با پیامد هر یک خلاصه می‌کند.

◆۱.۳ ویژگی‌های هستۀ I3C

I3C بر پایۀ حفظ رابط سریال دومیلۀ SCL و SDA، جهشی بزرگ را محقق کرده است.

◆۱.۳.۱ انتقال پرسرعت

فریم‌های دادهٔ I3C بر پایۀ SDR (Single Data Rate؛ نرخ دادهٔ تکی) استوارند و تا 12.5Mbit/s می‌رسند؛ بسیار فراتر از سقف I2C.

سرعت از درایو ترکیبی می‌آید: هنگام انتقال داده، گذرگاه با درایو پوشش‌ده (push-pull) رانده می‌شود و تنها در مرحله‌هایی مانند داوری و پاسخ (ACK/NACK) که به «وِی-اِند سیمی» نیاز دارند، به زه‌کش‌باز (open-drain) بازمی‌گردد. درایو پوشش‌ده نیازی به انتظار برای شارژ آهستۀ خازن یا مقاومت کشش‌بالای خارجی ندارد، سطح منطقی سریع‌تر جابه‌جا می‌شود و به همین دلیل است که SCL می‌تواند تا پلۀ 12.5Mbit/s بالا برود؛ زه‌کش‌باز نیز منطق داوری و پاسخ را همانند I2C تضمین می‌کند. جابه‌جایی درایو به‌طور خودکار توسط کنترل‌گر درون فریم انجام می‌شود و برای دستگاه‌ها شفاف است.

◆۱.۳.۲ نشانی‌دهی پویا (DAA)

دستگاه‌های فرستندۀ I3C دیگر نشانی ثابت ندارند؛ در زمان راه‌اندازی گذرگاه، کنترل‌گر با فرمان ENTDAA به هر دستگاه فرستندۀ I3C نشانی پویا تخصیص می‌دهد که در بازۀ 0x08~0x77 قرار دارد. دستگاه‌های هم‌مدل را می‌توان انبوه به کار گرفت و نشانی‌ها نیز به‌طور یکپارچه توسط کنترل‌گر مدیریت می‌شوند.

◆۱.۳.۳ وقفۀ درون‌گذرگاهی (IBI)

دستگاه‌های فرستندۀ I3C می‌توانند درخواست وقفه را مستقیماً روی SCL/SDA مطرح کنند، بدون پایۀ جداگانۀ INT؛ پذیرش یا رد درخواست را کنترل‌گر تصمیم می‌گیرد. در سناریوهای چند‌سنسوری، صرفه‌جویی در پایه‌های GPIO چشمگیر است.

وقفه از گذرگاه می‌گذرد، نه از پایه: دستگاه فرستنده هنگام آزاد بودن گذرگاه به‌طور فعال SDA را پایین می‌کشد و توالی آغازِ ویژه‌ای می‌فرستد تا «درخواست وقفه» را به کنترل‌گر برساند؛ جایگزین پایۀ مستقل وقفه (Interrupt/Data Ready) در I2C. هرچه شمار دستگاه‌ها بیشتر باشد، صرفه‌جویی در GPIO آشکارتر می‌شود.

وقفه‌های I3C به دسته‌های زیر تقسیم می‌شوند:

بدون داده: فقط درخواست فرستاده می‌شود و رخداد مشخص با خوانش بعدی یا رجیستر رخداد بیان می‌شود؛
همراه با داده: هنگام درخواست چند بایت رخداد نیز ضمیمه می‌شود و یک عملیات خواندن از کنترل‌گر کم می‌شود.

درخواست همیشه پذیرفته نمی‌شود: کنترل‌گر می‌تواند بنا بر بار کاری فعلی، IBI یک دستگاه را پاسخ دهد یا رد کند (NACK). در سناریوی چند‌کنترل‌گری، دستگاه فرستندۀ I3C می‌تواند در نقش «هدف» (target) گمارده شود و کنترل‌گرهای دیگر با IBI درخواست مدیریت نشست به آن بفرستند؛ توانی که دستگاه فرستندۀ I2C ندارد.

توجه: IBI تنها برای دستگاه‌های I3C کار می‌کند؛ دستگاه‌های legacy I2C پس از اتصال به گذرگاه، وقفه را همچنان فقط از راه پایۀ خارجی GPIO اعلام می‌کنند.

◆۱.۳.۴ قابلیت اطمینان

سازوکارهای کشف خطایی که I3C در لایۀ پروتکل معرفی می‌کند:

درستی‌سنجی نشانی: میدان نشانی فریم SDR بیت توازن فرد (odd parity) دارد؛
CRC داده: بخش داده می‌تواند به‌اختیار از CRC استفاده کند (CRC-8/CRC-32)؛
درستی‌سنجی رفتار و سیگنال ERR: فریم SDR می‌تواند داده‌ها و میدان‌های رفتاریِ پس از نشانی را گام‌به‌گام بازبینی کند؛ دستگاه فرستنده نیز می‌تواند با سیگنال ERR (Error) خطای فریم را به کنترل‌گر اعلام کند تا کنترل‌گر میان ارسال مجدد و خاتمۀ انتقال تصمیم بگیرد.

I2C تنها داوری در سطح گذرگاه و ACK/NACK دارد و خودِ پروتکل درستی‌سنجی بیت‌به‌بیت انجام نمی‌دهد؛ کشف خطا به نرم‌افزار بالادستی سپرده می‌شود (خواندن مجدد و مقایسه، یا محاسبۀ CRC در لایۀ کاربرد).

◆۲.۱ سازوکار سازگاری I3C

مشخصۀ MIPI I3C مقرر می‌کند که کنترل‌گر I3C باید سازگاری پسینی با I2C داشته باشد؛ دستگاه‌های I2C که به گذرگاه I3C متصل می‌شوند، در نقش دستگاه legacy (متعارف) — که در ادامه «دستگاه legacy» نامیده می‌شوند — حاضرند و کنترل‌گر I3C با حالت SDR و زمان‌بندی بایتیِ سازگار با I2C با دستگاه‌های I2C گفت‌وگو می‌کند. از دید پروتکل، آنچه کنترل‌گر به سوی دستگاه I2C می‌فرستد دقیقاً یک فریم انتقال متعارف I2C است:

START → 7bit Address + R/W → ACK → Data → ACK ... → STOP

برای دستگاه I2C، کنترل‌گر I3C و کنترل‌گر I2C تقریباً تفاوتی ندارند: روند دریافت دستگاه همچنان START / نشانی 7-bit به‌همراه R/W / ACK / داده، ... / STOP است و پاسخ‌دهی با زه‌کش‌باز به‌همراه کشش بالا انجام می‌شود؛ تفاوت‌هایی مانند جابه‌جایی پوشش‌ده/زه‌کش‌باز و زمان‌بندی فریم SDR درون کنترل‌گر رخ می‌دهند و دستگاه آن‌ها را درک نمی‌کند. روند خواندن و نوشتن درایور موجود نیازی به تغییر ندارد.

◆۲.۲ شیوۀ اتصال فیزیکی

I3C اجازه می‌دهد چندین دستگاه I2C و I3C هم‌زمان روی گذرگاه سوار شوند و به‌طور عادی ارتباط برقرار کنند. دو سناریوی رایج اتصال در شکل‌های زیر نشان داده شده است.

◆۲.۳ مدیریت نشانی و پیشگیری از تداخل

از آنجا که میان دستگاه‌های I2C و دستگاه‌های I3C ممکن است تداخل نشانی رخ دهد، برای پیشگیری از آن تمهیدی لازم است. نخست نشانی هر گروه از دستگاه‌ها را مرور می‌کنیم:

دستگاه‌های legacy I2C: نشانی ایستای ثابت 7-bit، وابسته به سخت‌افزار؛
دستگاه‌های I3C: نشانی پویا، تخصیص‌شدۀ کنترل‌گر در مرحلۀ DAA، در بازۀ 0x08~0x77؛
نشانی پخش 0x7E: مخصوص I3C است و برای ارسال فرمان‌های CCC به کار می‌رود (دستگاه‌های I2C معمولاً آن را نمی‌شناسند و پاسخی نمی‌دهند؛ از این رو بی‌اثر است).

هنگام اجرای DAA روی گذرگاه ترکیبی، کنترل‌گر نباید نشانی ایستای یک دستگاه I2C را دوباره به یک دستگاه فرستندۀ I3C تخصیص دهد. در پیاده‌سازی، کنترل‌گر جدولی از «نشانی‌های اشغال‌شده» نگه می‌دارد، نشانی‌های ایستای legacy را در آن ثبت می‌کند و در زمان DAA از آنها می‌گذرد.

◆۲.۴ مقداردهی اولیه و پیکربندی کنترل‌گر

در راه‌اندازی، نخست ساعت جانبۀ I3C، ساعت کارکرد جانبیِ AFIO و ساعت درگاه GPIOB فعال می‌شود تا پایۀ زمانی لازم برای پیکربندی‌های بعدی فراهم شود؛ سپس GPIO پیکربندی می‌شود: پایه‌های PB10 و PB11 به‌ترتیب به I3C_SCL و I3C_SDA گمارده می‌شوند، حالت پایه روی خروجی پوشش‌ده جانبی (GPIO_Mode_AF_PP) تنظیم و سرعت خروجی روی «سریع» قرار می‌گیرد تا بتواند نرخ ارتباط گذرگاه I3C را بر تابد.

سپس جانبۀ I3C پیکربندی می‌شود که در سه گام انجام می‌گیرد. گام نخست، پیکربندی پارامترهای زمان‌بندی گذرگاه I3C است، شامل زمان نگه‌داشت SDA، زمان انتظار، مدت سطوح بالا و پایین SCL در حالت پوشش‌ده و زه‌کش‌باز، زمان آزادسازی گذرگاه و زمان بیکاری گذرگاه؛ این پارامترها با هم نرخ ارتباط و ویژگی‌های زمان‌بندی گذرگاه I3C را تعیین می‌کنند. گام دوم، پیکربندی پارامترهای رفتاری کنترل‌گر I3C است، شامل نشانی پویای کنترل‌گر روی 0x22، غیرفعال‌سازی قابلیت اتصال گرم، غیرفعال‌سازی توقف پاسخ ACK، غیرفعال‌سازی توقف فرمان CCC، و غیرفعال‌سازی توقف ارسال و توقف دریافت؛ این پیکربندی‌ها حالت کار و راهبرد پاسخ کنترل‌گر را به‌عنوان دستگاه اصلی I3C تعیین می‌کنند. گام سوم، پیکربندی پارامترهای آستانۀ FIFO است، شامل آستانۀ FIFO دریافت و آستانۀ FIFO ارسال که هر دو روی برانگیختگی در ۱/۴ پر شدن تنظیم می‌شوند، و غیرفعال‌سازی FIFO کنترل؛ این پیکربندی‌ها سطح آستۀ بافر داده و نقطۀ برانگیختگی وقفه/DMA را تعیین می‌کنند.

در پایان، سه ساختار پیکربندی بالا به‌ترتیب با توابع I3C_Ctrl_Init، I3C_Ctrl_Config و I3C_SetConfigFifo در رجیسترهای سخت‌افزاری نوشته می‌شوند؛ پس از انجام همۀ پیکربندی‌های زیرین، فراخوانی I3C_Cmd(ENABLE) جانبۀ I3C را فعال می‌کند تا رسماً وارد حالت کار شود و به‌عنوان کنترل‌گر I3C پاسخ‌گوی ارتباط گذرگاه باشد.

void I3C_Config(void) { I3C_Ctrl_BusTypeDef I3C_Ctrl_BusInit = {0}; I3C_CtrlConfTypeDef I3C_CtrlConfInit = {0}; I3C_FifoConfTypeDef I3C_FifoConfInit = {0}; GPIO_InitTypeDef GPIO_InitStructure = {0}; RCC_PB2PeriphClockCmd(RCC_PB2Periph_AFIO, ENABLE); RCC_PB2PeriphClockCmd(RCC_PB2Periph_GPIOB, ENABLE); RCC_HBPeriphClockCmd(RCC_HBPeriph_I3C, ENABLE); /* PB10=SCL، PB11=SDA، خروجی پوشش‌ده جانبی */ GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10 | GPIO_Pin_11; GPIO_InitStructure.GPIO_Speed = GPIO_Speed_High; GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_PP; GPIO_Init(GPIOB, &GPIO_InitStructure); /* زمان‌بندی گذرگاه: میدان‌های Duration بر اساس ساعت کنترل‌گر تبدیل می‌شوند و * مقدار آن‌ها را فرکانس هدف SCL و مشخصات AC دستگاه مربوط تعیین می‌کند؛ * بخش پوشش‌ده و بخش زه‌کش‌باز و نیز فریم I3C و فریم legacy I2C جداگانه تعریف می‌شوند. */ I3C_Ctrl_BusInit.SDAHoldTime = I3C_SDAHoldTime_1_5; /* سطح بالای SCL در فریم I3C */ I3C_Ctrl_BusInit.SCLODLowDuration = 0x68; /* سطح پایین SCL در بخش زه‌کش‌باز */ I3C_Ctrl_BusInit.SCLI2CHighDuration = 0x48; /* سطح بالای SCL در فریم legacy I2C */ I3C_Ctrl_BusInit.BusFreeDuration = 0x67; /* تأخیر انتظار پاسخ دستگاه فرستنده */ I3C_CtrlConfInit.PullUp = ENABLE; I3C_CtrlConfInit.HotJoinAllowed_EN = DISABLE; I3C_CtrlConfInit.ACKStallState = DISABLE; /* بستن stall در مرحله‌ها (انتظار پاسخ دستگاه فرستنده) */ I3C_CtrlConfInit.CCCStallState = DISABLE; I3C_FifoConfInit.ControlFifo = I3C_CONTROLFIFO_DISABLE; I3C_Ctrl_Init(&I3C_Ctrl_BusInit); /* ارسال زمان‌بندی گذرگاه */ I3C_Ctrl_Config(&I3C_CtrlConfInit); /* ارسال رفتار کنترل‌گر */ I3C_SetConfigFifo(&I3C_FifoConfInit); /* ارسال پیکربندی FIFO */ I3C_Cmd(ENABLE); /* فعال‌سازی کنترل‌گر */ }

◆۲.۵ روند ارسال و دریافت

خواندن و نوشتن روی دستگاه‌های legacy I2C همان فریم متعارف I2C است.

روند ارسال —

START → [SlaveAddr | W=0] → ACK → [RegAddr] → ACK → [Data...] → ACK → STOP

روند دریافت —

Frame 1: START → [SlaveAddr | W=0] → ACK → [RegAddr] → ACK → STOP Frame 2: START → [SlaveAddr | R=1] → ACK → [D0] ACK ... [Dn-1] → NACK → STOP

◆۲.۶ کد نمونه

در این کد نمونه، با جانبۀ I3C عملیات خواندن و نوشتن روی یک دستگاه EEPROM سری AT24C02 انجام می‌شود.

uint32_t i2c_Transmit(uint8_t addr, uint8_t* send_buf, uint8_t send_len) { I3C_ClearFlag(I3C_FLAG_FCF); /* پاک‌سازی فلگ پایان فریم */ I3C_ClearFlag(I3C_CEVR_CERRF); /* پاک‌سازی فلگ خطا */ /* addr نشانی فرستنده 7-bit است؛ LEGACY_I2C فریم را با زمان‌بندی I2C می‌فرستد؛ پایان فریم STOP تولید می‌شود */ I3C_ControllerHandleMessage(addr, send_len, I3C_Direction_WR, I3C_CONTROLLER_MTYPE_LEGACY_I2C, I3C_GENERATE_STOP); for (size_t i = 0; i < send_len; i++) { while (I3C_GetFlagStatus(I3C_EVR_TXFNFF) == RESET) {} /* انتظار برای غیرپر بودن TX FIFO */ I3C_WriteByte(send_buf[i]); } while ((I3C_GetFlagStatus(I3C_EVR_FCF) == RESET) && (I3C_GetFlagStatus(I3C_EVR_ERRF) == RESET)) {} /* پایان فریم، یا خطا */ if (I3C_GetFlagStatus(I3C_EVR_ERRF) == SET) /* خطا: پس از پاک‌سازی فلگ خطا 1 بازمی‌گردد */ { I3C_ClearFlag(I3C_CEVR_CERRF); return 1; } if (I3C_GetFlagStatus(I3C_EVR_FCF) == SET) /* پایان: پاک‌سازی فلگ پایان فریم */ { I3C_ClearFlag(I3C_FLAG_FCF); } return 0; }

uint32_t i2c_Receive(uint8_t addr, uint8_t* recv_buf, uint8_t recv_len) { I3C_ClearFlag(I3C_FLAG_FCF); I3C_ClearFlag(I3C_CEVR_CERRF); I3C_ControllerHandleMessage(addr, recv_len, I3C_Direction_RD, I3C_CONTROLLER_MTYPE_LEGACY_I2C, I3C_GENERATE_STOP); for (size_t i = 0; i < recv_len; i++) { while (I3C_GetFlagStatus(I3C_EVR_RXFNEF) == RESET) {} /* انتظار برای غیرخالی بودن RX FIFO */ recv_buf[i] = I3C_ReadByte(); } while ((I3C_GetFlagStatus(I3C_EVR_FCF) == RESET) && (I3C_GetFlagStatus(I3C_EVR_ERRF) == RESET)) {} if (I3C_GetFlagStatus(I3C_EVR_ERRF) == SET) { I3C_ClearFlag(I3C_CEVR_CERRF); return 1; } if (I3C_GetFlagStatus(I3C_EVR_FCF) == SET) { I3C_ClearFlag(I3C_FLAG_FCF); } return 0; }

#define AT24CXX_PAGE_SIZE 8 /* هر صفحۀ AT24C02 برابر 8 بایت */ /* نوشتن تک‌بایتی: «نشانی‌دهی + داده» در یک فریم */ void AT24CXX_WriteOneByte(u16 WriteAddr, u8 DataToWrite) { uint8_t wr_data[] = {(uint8_t)WriteAddr, DataToWrite}; i2c_Transmit(0xA0 >> 1, wr_data, 2); /* مقدار 0xA0>>1 برابر 0x50 است، نشانی فرستنده 7-bit */ } /* خواندن تک‌بایتی: نخست نشانی مقصد نوشته می‌شود، سپس 1 بایت خوانده می‌شود (دو فریم) */ u8 AT24CXX_ReadOneByte(u16 ReadAddr) { uint8_t wr_data[] = {(uint8_t)ReadAddr}; uint8_t rd_data[1]; i2c_TransmitReceive(0xA0 >> 1, wr_data, 1, rd_data, 1); return rd_data[0]; } /* نوشتن صفحه‌ای: پیش از عبور از مرز صفحه، داده به تکه‌های هم‌اندازۀ صفحه بریده می‌شود و پس از هر صفحه، دورهٔ نوشتن داخلی منتظر می‌ماند */ u8 AT24CXX_WriteBytes(u16 WriteAddr, u8* pBuffer, u16 NumToWrite) { while (NumToWrite) { /* شمار بایت‌های باقی‌ماندۀ همین صفحه؛ در عبور از صفحه، بازگشت نشانی داده‌های آغاز صفحه را بازنویسی می‌کند و باید به مرز صفحه بریده شود */ u8 chunk = AT24CXX_PAGE_SIZE - (WriteAddr % AT24CXX_PAGE_SIZE); u8 wr_data[AT24CXX_PAGE_SIZE + 1]; u8 i; if (chunk > NumToWrite) { chunk = (u8)NumToWrite; } wr_data[0] = (u8)WriteAddr; for (i = 0; i < chunk; i++) { wr_data[i + 1] = pBuffer[i]; } if (i2c_Transmit(0xA0 >> 1, wr_data, chunk + 1) != 0) { return 1; } Delay_Ms(5); /* انتظار برای پایان دورهٔ نوشتن داخلی همین صفحه (حدود 5 ms) */ WriteAddr += chunk; pBuffer += chunk; NumToWrite -= chunk; } return 0; }
