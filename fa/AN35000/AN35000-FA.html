چکیده — جانبی ARGB زمان‌بندی پروتکل‌های کنترل چراغ WS2812، SK6812 و مانند آن‌ها را مستقیماً تولید می‌کند و راه‌حلی با دقت زمان‌بندی بالا، حافظۀ کم و بار پایین CPU ارائه می‌دهد؛ در حالی که طرح‌های SPI+DMA یا TIM+DMA به باد دادۀ ۸ تا ۱۶ برابری و پیش‌پردازش نرم‌افزاری نیاز دارند. پارامترهای T0H/T1H، دورۀ بیت داده و کد ریست آزادانه پیکربندی می‌شوند و مدل‌های متنوعی از LEDهای ARGB پشتیبانی می‌شوند. این سند مقایسۀ طرح‌های کنترل، روند توسعۀ نرم‌افزار (مقداردهی اولیۀ IO، DMA و ARGB) و سناریوهای کاربردی رایج را شرح می‌دهد.

◆۱.۲ مزایای اصلی جانبی اختصاصی ARGB

استفاده آسان و توسعه سریع و شهودی: در مقایسه با طرح‌های SPI+DMA یا TIM+DMA، جانبی اختصاصی ARGB به پیش‌پردازش داده پیش از هر بار تازه‌سازی نیاز ندارد؛ داده مستقیماً قالب GRB را پشتیبانی می‌کند که همان قالب بومی WS2812 است. کد پروتکل PIOC نیز به‌صورت نمونۀ مرجع فراهم شده و می‌توان مستقیماً آن را فراخوانی کرد.
نبود «باد داده»: طرح‌های SPI+DMA یا TIM+DMA با مصرف حافظه به اندازۀ چند برابر دادۀ خام همراه‌اند. برای نوارهای نورانی بلند — برای مثال ۱۰۲۴ LED — با روش معمولی SPI+DMA یا TIM+DMA حافظۀ مصرفی از 3KB به 24KB افزایش می‌یابد و منابع حافظه هدر می‌رود؛ جانبی اختصاصی ARGB و PIOC باد دادۀ حافظه ندارند.
سازگاری بالا: جانبی ARGB به کاربر اجازه می‌دهد طول سطح بالای کد ۰/۱ (T0H، T1H)، دورۀ کل کد ۰/۱ (DAT_ARR) و طول سیگنال ریست (RST_ARR) را آزادانه پیکربندی کند. با تنظیم این پارامترها می‌توان با LEDهای ARGB سازندگان مختلف با الزامات زمان‌بندی متفاوت — مانند WS2812، SK6812 (RGBW)، TM1814، UCS1903 و GS8208 — سازگاری برقرار کرد.
بار بسیار پایین CPU و آزادسازی توان محاسباتی: هنگام کنترل نوارهای نورانی بلند (مثلاً بیش از ۱۰۰۰ LED)، نرخ اشغال CPU تقریباً ۰٪ است. توان محاسباتی آزادشده می‌تواند الگوریتم‌های پیچیده‌تر افکت نور (مانند تحلیل طیف موسیقی و پیوند هوش مصنوعی لبه‌ای با افکت نور) را پشتیبانی کند.
سازوکار تازه‌سازی منعطف و مدیریت وقفه: وقفه‌های متعددی مانند تکمیل ارسال، نیمۀ انتقال، تکمیل بایت و تکمیل ریست فراهم است تا پیاده‌سازی قابلیت‌های پیشرفته مانند تعویض بافر دوگانه و به‌روزرسانی پویای افکت‌ها آسان شود.

◆۲.۱ روند توسعۀ نرم‌افزار

گام‌های توسعه به‌ترتیب عبارت‌اند از:

۱. مقداردهی اولیۀ IO
۲. مقداردهی اولیۀ DMA
۳. مقداردهی اولیۀ ARGB
۴. فعال‌سازی ارسال ARGB با ARGB_Cmd(ENABLE); و آغاز ارسال یک فریم داده

بسته به تراشۀ مختلف، IO متناظر با ARGB باید در حالت خروجی push-pull چندگانه (Alternate Function) پیکربندی شود؛ کارکرد دقیق هر پین را می‌توان در دیتاشیت منتشرشده در وب‌گاه رسمی مراجعه کرد. برای مثال در سری CH32V407 پین چندگانۀ ARGB پین PA15 است. کد پیکربندی CH32V407 به‌صورت زیر است:

void ARGB_GPIO_Init() { GPIO_InitTypeDef GPIO_InitStructure; RCC_PB2PeriphClockCmd(RCC_PB2Periph_GPIOA, ENABLE); GPIO_InitStructure.GPIO_Pin = GPIO_Pin_15; GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_PP; GPIO_InitStructure.GPIO_Speed = GPIO_Speed_High; GPIO_Init(GPIOA, &GPIO_InitStructure); }
کد ۱مقداردهی اولیۀ GPIO برای ARGB

بسته به تراشۀ مختلف، کانال DMA پیکربندی می‌شود؛ ممکن است ARGB تراشه‌های مختلف به کانال‌های DMA متفاوتی متصل باشد. حالت انتقال DMA پیشنهاد می‌شود همواره روی DMA_Mode_Normal ثابت بماند و طول انتقال DMA بر اساس نیاز پیکربندی می‌شود؛ اما توجه شود که طول انتقال DMA باید دقیقاً با طول دورۀ تازه‌سازی دادۀ ARGB برابر باشد. کد پیکربندی CH32V407 به‌صورت زیر است:

void ARGB_WS2812B_DMA_Init(uint8_t *ARGB_DMA_Buffer, size_t buffer_size) { RCC_HBPeriphClockCmd(RCC_HBPeriph_DMA1, ENABLE); DMA_InitTypeDef DMA_InitStructure; DMA_InitStructure.DMA_PeripheralBaseAddr = (uint32_t)&(ARGB->DATAR); DMA_InitStructure.DMA_MemoryBaseAddr = (uint32_t)ARGB_DMA_Buffer; DMA_InitStructure.DMA_DIR = DMA_DIR_PeripheralDST; DMA_InitStructure.DMA_BufferSize = buffer_size; DMA_InitStructure.DMA_PeripheralInc = DMA_PeripheralInc_Disable; DMA_InitStructure.DMA_MemoryInc = DMA_MemoryInc_Enable; DMA_InitStructure.DMA_PeripheralDataSize = DMA_PeripheralDataSize_Byte; DMA_InitStructure.DMA_MemoryDataSize = DMA_MemoryDataSize_Byte; DMA_InitStructure.DMA_Mode = DMA_Mode_Normal; DMA_InitStructure.DMA_Priority = DMA_Priority_High; DMA_InitStructure.DMA_M2M = DMA_M2M_Disable; DMA_Init(DMA1_Channel10, &DMA_InitStructure); DMA_Cmd(DMA1_Channel10, ENABLE); }
کد ۲مقداردهی اولیۀ کانال DMA متصل به ARGB

در پیکربندی ARGB توجه شود که پارامترهای پروتکل تک‌خطی مانند T1H بر اساس ساعتِ گذرگاه ساعتی که ARGB به آن متصل است محاسبه می‌شوند. برای مثال در سری CH32V407، ARGB زیر گذرگاه ساعتی HB قرار دارد و ساعت گذرگاه HB در این سری با ساعت هسته برابر است؛ بنابراین می‌توان مقدار قابل‌نوشتن در رجیستر را مستقیماً با SystemCoreClock محاسبه کرد. در غیر این صورت، باید با ساختار ساعت سیستم یا با فراخوانی مستقیم تابع void RCC_GetClocksFreq(RCC_ClocksTypeDef *RCC_Clocks); ساعت گذرگاه ساعتیِ محل استقرار ARGB در آن پلتفرم به‌دست آید و سپس مقدار قابل‌نوشتن در رجیستر محاسبه شود.

#define ARGB_MS2HBTICK(ms) ((uint32_t)((float)SystemCoreClock / 1000.0f * (float)ms)) #define ARGB_US2HBTICK(us) ((uint32_t)((float)SystemCoreClock / 1000000.0f * (float)us)) #define ARGB_NS2HBTICK(ns) ((uint32_t)((float)SystemCoreClock / 1000000000.0f * (float)ns)) void ARGB_WS2812B_Init(uint8_t *ARGB_DMA_Buffer, size_t buffer_size) { // Enable the clock for ARGB peripheral RCC_HBPeriphClockCmd(RCC_HBPeriph_ARGB, ENABLE); // Initialize ARGB configuration structure ARGB_InitTypeDef ARGB_InitStruct; // Configure ARGB parameters ARGB_InitStruct.ARGB_Length = buffer_size - 1; // Set buffer length (minus 1 for zero-based indexing) ARGB_InitStruct.ARGB_T1H = ARGB_US2HBTICK(0.9f); // Set high time for '1' bit ARGB_InitStruct.ARGB_T0H = ARGB_US2HBTICK(0.3f); // Set high time for '0' bit ARGB_InitStruct.ARGB_DataPeriod = ARGB_US2HBTICK(1.45f); // Set data bit period ARGB_InitStruct.ARGB_RSTPeriod = ARGB_US2HBTICK(80.0f); // Set reset period ARGB_InitStruct.ARGB_Mode = ARGB_Mode_SendRSTFirst; // Set mode to send reset first ARGB_InitStruct.ARGB_Endian = ARGB_Endian_MSB; // Set most significant bit first ARGB_Init(&ARGB_InitStruct); // Apply ARGB configuration // Enable ARGB interrupt for frame reception complete ARGB_ITConfig(ARGB_IT_FRH, ENABLE); // Enable ARGB interrupt in the NVIC NVIC_EnableIRQ(ARGB_IRQn); ARGB_WS2812B_DMA_Init((void *)ARGB_DMA_Buffer, buffer_size); }
کد ۳مقداردهی اولیۀ جانبی ARGB با پروتکل WS2812B
توجه: هنگام آغاز دوبارۀ یک فریم انتقال، لازم است طول انتقال و آدرس آغاز انتقال DMA دوباره پیکربندی شوند.

نمونه: نمونۀ زیر روی نمایشگر نقطه‌ای 8×8 متشکل از WS2812، دادهٔ تصویری چندفریمی قالب GRB تولیدشده از یک پروندۀ GIF را نمایش می‌دهد.

◆۲.۲ سناریوهای کاربردی رایج

■ سیستم‌های روشنایی هوشمند بزرگ‌مقیاس:

توصیف سناریو: روشنایی منظر شهری، نور دورنمای ساختمان، پرده پس‌زمینۀ بزرگ صحنه (نوارهای نورانی به طول چند صد متر و ده‌ها هزار LED).
ویژگی راه‌حل: رانندگی آسان نوارهای نورانی بسیار بلند بدون افت فریم؛ پشتیبانی از ساخت افکت‌های نورانی پویا، هم‌گام و پیچیده.

■ لوازم جانبی بازی‌محور و نورپردازی محیط دسکتاپ:

توصیف سناریو: نور پس‌زمینۀ کیبورد مکانیکی، افکت نور ماوس، نوار نورانی رنگین‌کمانی داخل کیس رایانه، نوار نور کاهش‌دهندۀ خیرگی مانیتور.
ویژگی راه‌حل: پشتیبانی از SK6812 (RGBW) چهارکاناله با بازنمایی رنگ ظریف‌تر؛ تأخیر پایین در سطح سخت‌افزار که تضمین می‌کند افکت‌های نور بدون لگ به‌صورت بی‌درنگ به تصویر بازی و ریتم موسیقی (مانند حالت ریتمیک) پاسخ دهند.

■ نورپردازی داخلی و خارجی خودرو:

توصیف سناریو: نور پای پیاده داخل کابین، راهنمای روان روی پنل درب، چراغ خوش‌آمدگویی پویای جلوپنجره.
ویژگی راه‌حل: پایداری بالا. جانبی اختصاصی ARGB عدم‌قطعیت زمان‌بندی شبیه‌سازی نرم‌افزاری را حذف می‌کند و تضمین می‌سازد افکت نور در محیط الکترومغناطیسی پیچیدۀ خودرو همچنان پایدار، مطمئن و بدون سوسو زدن بماند.

■ مصورسازی موسیقی و نصب‌های تعاملی:

توصیف سناریو: نور ریتمیک بلندگوی بلوتوثی، نصب‌های هنری تعاملی، نورپردازی تزئینی بار.
ویژگی راه‌حل: CPU می‌تواند با تمام توان الگوریتم FFT (تبدیل فوریه سریع) را برای تحلیل صدا اجرا کند و هم‌زمان نتیجه را از طریق DMA به جانبی ARGB بفرستد؛ هم‌گام‌سازی افکت نور با موسیقی به‌سادگی انجام می‌شود.

اصطلاحات فنی سخت‌افزار مطابق سند اصلی به‌صورت انگلیسی حفظ شده‌اند. جدول زیر معادل‌ها و شرح کوتاه هر واژه را برای مرجع سریع جمع می‌کند.

واژهیعنی چه؟
ARGBجانبی اختصاصی تولید زمان‌بندی پروتکل‌های کنترل نور آدرس‌پذیر؛ بدون پردازش هسته و با ارسال مستقیم دادۀ خام GRB
WS2812 / SK6812LEDهای هوشمند تک‌خطی رایج؛ SK6812 در نوع RGBW کانال سفید مستقل دارد
TM1814 / UCS1903 / GS8208مدل‌های دیگر LED تک‌خطی با زمان‌بندی متفاوت که با تنظیم پارامترها پشتیبانی می‌شوند
PIOCکنترل‌کنندۀ ورودی/خروجی برنامه‌پذیر؛ کد اسمبلی پروتکل را مستقل از هسته اجرا می‌کند و راه‌حل جایگزین جانبی ARGB است
T0H / T1Hطول سطح بالای پالس برای کد ۰ و کد ۱؛ بر اساس تیک‌های ساعت گذرگاه میزبان ARGB محاسبه می‌شود
DAT_ARRدورۀ کل بیت داده؛ مجموع طول سطح بالا و سطح پایین هر بیت
RST_ARRطول سیگنال ریست (خط Latch) برای قفل‌کردن رنگ‌های نمایش‌شده؛ برای WS2812 حدود 80µs
GRBترتیب بایت‌های رنگ در قالب بومی WS2812؛ دادۀ بافر بدون پیش‌پردازش مستقیماً ارسال می‌شود
Data Bloatباد دادۀ حافظه؛ در طرح‌های SPI+DMA/TIM+DMA هر بیت رنگ به ۱ یا ۲ بایت گسترش می‌یابد (۸ تا ۱۶ برابر)
Half-Transfer / Frame-Readyوقفه‌های نیمۀ انتقال و آمادگی فریم؛ برای تعویض بافر دوگانه و به‌روزرسانی پویای افکت‌ها
Interconnect MCUمیکروکنترلرهای اینترکانکت WCH مانند CH32V467/V407/X315 با گذرگاه‌های گسترده و جانبی‌های پرسرعت
HBTICKیک تیک ساعت گذرگاه HB؛ در CH32V407 برابر تیک ساعت هسته است و با SystemCoreClock محاسبه می‌شود
GD / GIFکتابخانۀ رمزگشای GIF در نمونۀ رسمی؛ هر فریم به‌صورت بافر GRB به DMA داده می‌شود
